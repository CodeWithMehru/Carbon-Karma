# Carbon Karma 🌱

**Carbon Karma is a gamified platform that helps individuals in India understand, track, and reduce their carbon footprint through AI-powered insights and simple daily actions.**

Snap a photo of a grocery receipt or utility bill and Google **Gemini Vision** extracts the items and estimates their CO₂ impact using India-specific emission factors. Every sustainable choice earns **Karma** points, builds a daily **streak**, and ripples out to a live community feed.

> **Chosen vertical:** Carbon Footprint Awareness Platform — _"helps individuals understand, track, and reduce their carbon footprint through simple actions and personalized insights."_

---

## 🧭 How it works — Understand → Track → Reduce

| Stage          | What the user does                                                             | How Carbon Karma helps                                                                                                       |
| -------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| **Understand** | Completes a 5-step baseline quiz (energy, transport, diet, flights, shopping). | Computes a personalized **monthly baseline** from India-specific emission factors.                                           |
| **Track**      | Scans receipts/bills and logs daily eco-actions.                               | Gemini parses receipts; the dashboard shows **current footprint vs baseline**, updated live.                                 |
| **Reduce**     | Follows personalized insights, logs one-click actions, keeps a streak.         | **Gemini-personalized insights** target the user's biggest sources; **streaks** and a **reduction %** keep momentum visible. |

## 🏆 Key Features

- **Gemini AI Receipt Parser** — Upload a bill or receipt; Gemini Vision strictly validates that the image is a real receipt (rejecting non-receipts), extracts items, and estimates CO₂ per item. A deterministic mock parser is used automatically when no API key is configured, so the app always works.
- **Personalized Baseline Quiz** — Generates your monthly carbon baseline using India-specific factors (CEA grid 0.82 kg CO₂/kWh, transport, LPG/PNG, diet, flights).
- **Personalized AI Insights** — Three targeted reduction tips derived from your **biggest emission sources**. Generated by Gemini on the dashboard, with a fully deterministic fallback engine (`lib/insights`) when the AI is unavailable.
- **One-Click Quick Actions** — Log eco-actions straight from the dashboard; Karma, carbon saved, and your streak update immediately.
- **Daily Streak & Reduction Metric** — A consecutive-day streak plus a headline "% below baseline pace" make the _reduce_ part of the journey visible.
- **Community Ripple Feed & Impact Map** — Anonymized community actions and city-level leaderboards.

## 🏗️ Architecture

- **`proxy.ts`** (Next.js 16's renamed middleware) — refreshes the Supabase session, guards authenticated routes, and **rate-limits the AI routes** (30 req/min per IP, with `Retry-After`). Auth resolution is fault-tolerant: a Supabase outage degrades to "logged out" instead of a 500.
- **Server Actions** (`app/**/actions.ts`) — all mutations (onboarding, logging actions, confirming receipts) run server-side against the fully-typed Supabase client.
- **`lib/` domain logic** — pure, framework-free, and unit-tested: carbon calculator, karma & receipt scoring, streak rules, and the insights engine. This separation is why coverage of the domain logic is ~99%.
- **Row Level Security** — every table is user-scoped (`auth.uid()`), with `WITH CHECK` on inserts/updates. Karma totals are owned by the application layer (single source of truth), so the `karma_transactions` table is a clean audit ledger.

```
app/            App Router pages, route handlers (app/api/ai/*), and server actions
components/     UI + dashboard widgets (incl. the accessibility menu, dynamic chart loader)
lib/            Pure domain logic: carbon, karma, streak, insights, validators, ai, supabase
types/          Supabase Database types (fully typed client → zero `as any`)
supabase/       schema.sql (tables, RLS policies, views, seed actions)
tests/          unit/ + integration/ (Vitest) and e2e/ (Playwright)
```

## 🚀 Getting Started

### Prerequisites

- Node.js 20+
- A free [Supabase](https://supabase.com) project
- A [Google Gemini API key](https://aistudio.google.com/) (optional — the app falls back to a mock parser without one)

### Setup

```bash
git clone https://github.com/CodeWithMehru/Carbon-Karma.git
cd Carbon-Karma
npm install
```

1. **Create the database:** In your Supabase project, open the SQL Editor and run [`supabase/schema.sql`](supabase/schema.sql). This creates the tables, RLS policies, analytics views, and seed eco-actions.
2. **Configure environment:** Copy the template and fill in your keys.
   ```bash
   cp .env.local.example .env.local
   ```
   ```env
   NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
   GEMINI_API_KEY=your_gemini_api_key        # optional (mock parser used if absent)
   NEXT_PUBLIC_APP_URL=http://localhost:3000
   ```
3. **Run it:**
   ```bash
   npm run dev
   ```
   Open <http://localhost:3000>.

### Scripts

| `npm run dev`           | Start the dev server (Turbopack)                         |

## ✅ Quality, per category

### Testing

- **211 unit & integration tests** across 10 Vitest suites: the carbon calculator (electricity/transport/food/cooking-fuel/baseline, plus edge cases — zero, negative, large, fractional, India factors), karma levels & progression, receipt karma scoring, daily-streak rules, the insights engine, Zod validators, and security headers.
- **Integration tests** exercise the server-action orchestration (`logEcoAction`, `confirmAndLogReceipt`) against a mocked Supabase client with a frozen clock.
- **~99% statement / 100% line coverage of the domain logic** (`npm run test:coverage`).
- **Playwright E2E**: hermetic public flows (landing, auth validation, route protection, security headers, 404), accessibility checks + **axe-core** scans, and guarded authenticated flows (skipped unless `E2E_EMAIL`/`E2E_PASSWORD` are set, so the suite is always green).

### Code Quality

- Strict TypeScript with **zero `as any`** — the Supabase client is fully typed via `types/database.ts`. Removing the casts surfaced and fixed real bugs (a non-existent `full_name` column, an invalid `energy` category enum, and double-counted karma).
- Clean separation of concerns (pure `lib/` domain logic vs. server actions vs. UI), a small logging boundary (`lib/logger.ts`), Prettier formatting, and **zero ESLint warnings**.

### Security

- **Row Level Security** on every table with `WITH CHECK` constraints.
- **Rate limiting** on all `/api/ai/*` routes (30/min/IP) with `Retry-After` headers.
- **Zod validation** at every boundary, including the Gemini output (a custom error type ensures only user-safe messages are surfaced — internal errors never leak).
- **Security headers**: CSP, HSTS, `X-Frame-Options: DENY`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`. `'unsafe-eval'` is dropped from the **production** CSP (kept only for dev HMR).
- Secrets are git-ignored; only `.env.local.example` is committed.

### Accessibility

- A **reachable accessibility menu** (keyboard-operable, `role="switch"`) toggles a **high-contrast theme** and a **dyslexia-friendly font**, persisted across sessions.
- Skip-to-content link, semantic landmarks, ARIA regions and live regions, associated form labels with `aria-describedby`/`aria-invalid`, visible focus rings, and `prefers-reduced-motion` support.
- Automated **axe-core** scans gate the landing and login pages in CI.

### Efficiency

- Recharts is **dynamically imported** (`ssr: false`) so the charting bundle stays out of the initial payload; server components by default; `optimizePackageImports` for `lucide-react`/`recharts`/`framer-motion`; Turbopack builds.
- Removed unused heavy dependencies (`three` / `@react-three/*`) for a leaner dependency tree.

## 📐 Assumptions

- Electricity is estimated from the monthly bill at **₹8/kWh** and the **CEA 2023–24 grid factor of 0.82 kg CO₂/kWh**.
- Commute emissions assume a round-trip over ~22 working days/month; flights are annualized and spread monthly.
- Receipt CO₂ estimates and the "~1.5 kg saved per sustainable item" heuristic are directional, intended to drive behavior change rather than serve as a certified audit.
- Karma: 100 onboarding bonus; 50 per receipt + 10/sustainable + 5/neutral item; eco-actions carry per-action rewards. Levels increase every 100 points.
